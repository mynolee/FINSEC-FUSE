## 추가 보안·복구 검증

- 증거 종류별 신뢰 발급자 강제: 종류가 다른 등록 발급자의 재해시된 PASS/FAIL을 거부하고, 잘못된 복구 요청은 상태를 변경하지 않음
- 위임: 원본 바이트 인증, 만료, 관계없는 부모, 현재 거래·위험 장부·소비된 승인, 선택적 신청 식별자의 신뢰 워크플로 바인딩
- 외부 위조 입력 거부가 정상 워크플로의 격리·상태 변경으로 이어지지 않는 경계 시험
- 누락 증거 보완 및 실제 증거 저장소 SQL 장애 후 generation 2·새 결과·새 승인으로 모의 지급
- 정상 소득 부적격, 직원 거절 재요청, 무관한 문서 v2 격리가 안전한 v1 업무·승인을 방해하지 않는 시험
- 실제 PostgreSQL에서 서로 다른 고객 및 같은 고객의 별도 신청을 동시 실행
- KYC 실행 중 강제 종료, 지급 claim 후/예약 후 강제 종료, 지급 commit 후 응답 손실과 재시도, 실제 PostgreSQL 중단·재시작
- 장애 복구: 중복 지급·중복 위험 RELEASE 방지, 사용 위험 유지, 잔여 예약 해제, 의존 DB 중단 시 정제된 503/ERROR
- 화면·CLI·CI 결과물은 정제된 내보내기만 사용. 원문·비밀정보가 들어갈 수 있는 진단 로그/응답/브라우저 녹화는 게시하지 않음

## 원본 계약과의 차이

초기 60개 평가 사례는 원본 계약 묶음을 확보하기 전에 재구성했습니다. 원본을 확보한 뒤 경계·복구 인수 시험을 추가했지만, 기존 120행을 원본 60개 사례 전체의 동일 실행이라고 표시하지 않습니다. 원본과 구현의 역할 이름·일부 사유 코드·상태 전이 표현이 다르고 원본 내부에 상충하는 기대값도 있어 별도 대조가 필요합니다.

원본 서명 기준 벡터 1개를 실제 Java 바이트 검증기로 대조한 15개 검사와 원본 참고 Python 시험 23개는 통과했습니다. 이는 전체 DB 정책 Gate의 원본 호환성 검증이 아닙니다. 역할 이름을 변환한 서명은 원본 서명과 동일하다고 주장하지 않습니다. 원본 자료와 매핑 문서는 비공개로 유지합니다.

## 아직 검증하지 않은 범위

- v2.1 최신 보안 인수조건 전체에 대한 완전한 실행 증거. 일부 항목은 단위/통합 수준만 검증됨
- 선택 사항인 비공개 개발 도구 설치기는 설치·실행하지 않음
- 원본 인수 CSV 전체를 동일 조건으로 실행한 결과
- 독립적인 새 팀원의 문서 기반 전체 walkthrough. CI 성공만으로 별도 사람의 재현을 주장하지 않음
- 실제 Compose/브라우저 CI는 위 리비전에서 실행했으나, 모든 기기·브라우저·접근성 또는 운영 네트워크를 검증한 것은 아님
- LIVE 목적지 제한, metadata/host-gateway 차단, IPv6 소켓 격리와 배포 TLS/egress. 확인한 IPv4 합성 네트워크 범위를 확대 해석하지 않음
- 실제 외부 LLM·유료 API·실제 금융망: 호출하지 않음. LIVE 관련 시험은 가짜 제공자/로컬 HTTP 사용
- 운영 성능·장기 부하·금융기관 보안 인증·운영 배포

전체 프로젝트 완료율이나 AI 활용률은 이 시험 개수로 환산하지 않습니다.
