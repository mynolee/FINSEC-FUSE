# Local supply-chain checks

Run from repository root in an isolated Python 3.12 environment:

```
python -m pip install -r scripts/security/requirements.txt
python scripts/security-scan-test.py
./gradlew --no-daemon --console=plain writeDependencyInventory
python scripts/security-scan.py
```

The selected tool versions and transitive scanner environment are pinned in
requirements.txt/requirements.lock. These are reproducibility pins, not a claim
that they are current or vulnerability-free. The Java application versions are
controlled separately by the project build. Never automatically upgrade them
in response to a scanner finding.

Semgrep uses only the local targeted rule file, with metrics and version checks
disabled. detect-secrets uses local detection with verification disabled. Neither
scanner receives private source-pack siblings, personal agent instructions,
private prompts, .env files, caches or symlink targets. Python/npm audit and OSV
Maven queries send public dependency names and versions to advisory services;
they do not upload application source. Scanner subprocesses receive only an
allowlisted execution environment, without application credentials.

The public report contains aggregate counts, versions, hashes and fixed scope
labels. Raw findings, paths, source snippets and diagnostics are never printed or
uploaded. For authorized local investigation, --private-reports may name an
existing directory outside this repository; do not share that directory. Actual
SBOM JSON is retained there when explicitly requested, while CI publishes only
its component counts. Without that option, raw outputs are discarded.

Missing tools, mismatched versions, missing or invalid reports, empty collection,
skipped packages and scanner errors block the gate. All findings currently block;
there are no automatic suppressions. Individually reviewed synthetic false positives
require an APPROVED secret-review.json record matching path, type, line, secret
hash, whole-file hash, reason and unexpired review date. Pending review records do not suppress findings. File changes, new findings and
expired reviews require a fresh independent review. A heuristic finding
is not automatically proof that a real credential leaked. Investigate privately,
fix actual issues and rerun; never turn scanners off to obtain a passing result.

The Maven dependency inventory is generated by Gradle resolution, not inferred
from declared direct dependencies. OSV API v1 checks runtime and test coordinates.
Python SBOM consumes pip-audit's resolved package inventory; npm SBOM consumes the
lockfile. These checks do not inventory container operating-system packages.

Dependency review requires an explicit reviewed manifest fingerprint record.
The initial PENDING record blocks release. A reviewer must document the decision,
impact tests and matching SHA-256 values, then set status APPROVED. Any later
manifest mutation fails until reviewed again. A changed review file itself also
requires human review; repository code cannot prove an approval author's identity.

Targeted SAST and scanner synthetic fixtures are not complete application security
coverage. API/Service, real PostgreSQL, browser, independent review and the private
installer's SC-T21 tests remain separate requirements. No scanner result certifies
production banking safety or regulatory compliance.
